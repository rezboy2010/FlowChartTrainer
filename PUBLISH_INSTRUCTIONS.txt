ПУБЛИКАЦИЯ ТРЕНАЖЁРА НА GITHUB PAGES
Автор: Резяпкин Александр
Репозиторий: https://github.com/rezboy2010/FlowChartTrainer

1. Распакуй ЭТОТ архив в новую пустую папку через «Извлечь всё».
   Открой папку, в которой одновременно видны src, tests, docs и .github.
   Это готовые исходники. Удалять bin, obj или другие папки не требуется.

2. В репозитории GitHub открой Settings → Pages.
   В разделе Build and deployment выбери Source → GitHub Actions.
   Дополнительные шаблоны выбирать и создавать не нужно.

3. Вернись на Code. Нажми Add file → Upload files.
   В Проводнике выдели всё СОДЕРЖИМОЕ распакованной папки.
   МЫШЬЮ ПЕРЕТАЩИ выделенное в область загрузки GitHub.
   Загружать нужно папки целиком с их содержимым. Не выбирай вручную
   все вложенные файлы через «choose your files»: так можно потерять пути.
   ZIP-архив вместо исходников не загружай.

4. Перед подтверждением проверь, что пути сохраняются. Например:
   src/FlowchartTrainer.Web/FlowchartTrainer.Web.csproj
   src/FlowchartTrainer.Core/Logic/SchemeRunner.cs
   tests/FlowchartTrainer.Tests/Program.cs
   .github/workflows/pages.yml
   Если видны только имена без папок, отмени загрузку и повтори перетаскивание.
   Внизу выбери Commit directly to the main branch и Commit changes.

5. После загрузки в корне должны появиться src, tests, docs и .github.
   Если от предыдущей загрузки в корне остались Program.cs и
   FlowChartTrainer.csproj, удали только эти две лишние копии через меню
   файла «…» → Delete file → Commit changes.
   НЕ удаляй Directory.Build.props, global.json и FlowchartTrainer.sln.

6. Открой Actions → Deploy Blazor to GitHub Pages.
   Дождись зелёной галочки. Обычно сборка занимает несколько минут,
   точное время зависит от очереди GitHub.
   Если процесс не запустился: выбери его слева → Run workflow → main
   → Run workflow. Эта кнопка доступна при наличии pages.yml в main.

7. После успешной публикации открой:
   https://rezboy2010.github.io/FlowChartTrainer/
   Это ОЖИДАЕМЫЙ адрес; до первой успешной публикации он может выдавать 404.
   Точный адрес также показан в Settings → Pages.
   Если появился красный крестик, открой неудавшийся шаг и передай ошибку.

8. Проверь ссылку в приватном окне, без входа в GitHub. Пройди практику
   и тест. Затем проверь в другом браузере или на другом устройстве и дай
   другому ученику пройти приложение. Реальные результаты запиши в
   docs/CLASSMATE_TEST.md.

КАК ЭТО РАБОТАЕТ
GitHub Actions устанавливает SDK, запускает проверки C#, собирает Blazor,
определяет путь приложения из настроек Pages и публикует статические файлы.
Расчёты на C# выполняются в браузере посетителя. Отдельный сервер и
установленный .NET ему не нужны. Изменение main запускает новую сборку.
Локально по-прежнему можно запускать start.bat.
