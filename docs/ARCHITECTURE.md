# Устройство приложения

## Выбор технологии

C# отвечает требованию о строго типизированном языке. На нём реализованы модели, вычисления, проверка ответов и управление состоянием. Blazor WebAssembly связывает C# с кнопками, полями и SVG, выполняя приложение в браузере. Учебному тренажёру не нужны серверные записи, аккаунты и сетевые запросы для проверки каждого шага.

Преимущества: один язык для вычислений и интерактивного интерфейса; одна модель схемы для проверки и рисунка; обычные C#-проверки; размещение как статического сайта. Ограничения: первая загрузка включает среду .NET; для сборки нужен SDK; ресурсы нужно отдавать по HTTP(S), а не открывать через `file://`.

HTML описывает элементы страницы, CSS — внешний вид, SVG — фигуры и стрелки. Эти технологии не заменяют основную логику на C#.

## Части и их размещение

| Часть | Файлы | Ответственность |
|---|---|---|
| Типизированная модель | `src/FlowchartTrainer.Core/Models/` | Виды блоков, операнды, выражения, условия, цель задачи, снимок шага |
| Учебные данные | `Core/Data/TaskCatalog.cs`, `QuizCatalog.cs` | Три схемы с координатами и переходами; пять вопросов |
| Вычисления | `Core/Logic/SchemeRunner.cs` | Выполнение схемы; трасса; проверка цели; поиск всех решений |
| Проверка ответов | `Core/Logic/AnswerChecker.cs` | Разбор целого числа, диапазон, сравнение ответа с результатом шага |
| Состояние | `Core/State/TrainingSession.cs`, `QuizSession.cs` | Вход, текущий шаг, ответы, подтверждённые шаги, балл |
| Интерфейс | `Web/App.razor`, `Web/Components/` | Навигация и отображение данных модели |
| Оформление | `Web/wwwroot/css/app.css` | Цвета, размеры, адаптация, выделения |
| Проверки | `tests/FlowchartTrainer.Tests/Program.cs` | Проверка вычислений и взаимодействия логики с состоянием |

`Core` — сокращение от каталога `src/FlowchartTrainer.Core`, `Web` — от `src/FlowchartTrainer.Web`.

Вычисления не зависят от Blazor, SVG и CSS. Это позволяет проверять их отдельно от браузера. Для схем используется небольшой набор типов (`AssignmentNode`, `DecisionNode` и другие), а не исполнение строк с формулами.

## Движение данных: «Проверить вычисление»

1. `Practice.razor` показывает выражение и его числовую подстановку. Ученик вводит ответ в `Session.StepAnswer`.
2. Нажатие кнопки вызывает `TrainingSession.Check()`.
3. Сессия передаёт `CurrentStep`, ответ и выбранную ветвь в `AnswerChecker.CheckStep()`.
4. Проверка возвращает `CheckResult`. При ошибке индекс шага и видимые значения не меняются; появляется пояснение. При верном ответе сессия отмечает шаг подтверждённым.
5. Blazor повторно рисует компоненты. `VariablesTable.razor` показывает старое и новое значения, а «Следующий шаг» становится доступен.
6. `TrainingSession.Next()` увеличивает индекс и очищает поле ответа для следующего шага.

## Где и когда считаются значения

При нажатии «Разобрать число» сессия проверяет вход и вызывает `SchemeRunner.Run()`. Исполнитель проходит схему целиком и создаёт трассу — список `ExecutionStep` со снимками `Before` и `After`. Метод `BeginAtFirstAction()` устанавливает первым видимым шагом вычисление: блоки «Начало» и «Ввод x» остаются в трассе и подсвечиваются как пройденные. Интерфейс показывает только текущий шаг; вычисленное значение скрыто до правильного ответа. Трасса не содержит оценок за действия ученика: их хранит сессия.

Это обычный учебный тренажёр, а не защищённый экзамен: технически данные в браузере доступны посетителю. Скрытие будущих ответов — поведение интерфейса, а не защита от исследования кода.

`TaskCatalog` хранит семантические переходы в блоках и геометрию стрелок в `SchemeEdge`. Исполнитель выбирает `NextNodeId`; рисунок подсвечивает соответствующую пару «из/в». Текст формулы и числовая подстановка создаются выражениями модели. Проверка ответа, пояснение и таблица используют одну трассу.

Ветвление не меняет переменные: для условия снимки одинаковы. Присваивание сначала вычисляет правую часть со старыми значениями и только затем заменяет переменную. Для каждого шага создаётся отдельная копия словаря.

## Хранение и сброс

`App.razor` создаёт по одной сессии практики и теста. Они живут в памяти приложения и передаются компонентам. Переход в другой раздел не уничтожает эти объекты. Примеры теории имеют отдельную демонстрационную трассу.

`SetInput()` и `SelectTask()` очищают трассу и подсказки; `Restart()` начинает новую попытку с тем же текстом x. После перезагрузки `App` создаётся заново: прежний прогресс отсутствует. Браузерное хранилище и сервер не используются.

## Корректность

- Число разбирается через `long.TryParse` со знаком; дроби и текст отклоняются. Проверяется включённый диапазон.
- `SchemeRunner` отдельно проверяет диапазон, поэтому его нельзя обойти прямым вызовом логики из другого компонента.
- Арифметика выполняется в `checked` и обнаруживает переполнение. Текущие диапазоны намного меньше предела `long`.
- Исполнитель обнаруживает циклы и отсутствующие переходы; требует вывод и завершение.
- `FindSolutions()` перебирает небольшой конечный диапазон и запускает ту же схему. Все подходящие числа принимаются по цели, единственный ответ не зашит в проверку.
- При неверном шаге `Next()` не увеличивает индекс. Повторная проверка вопроса теста не начисляет балл повторно.

## Размещение

Сборщик C# создаёт файлы WebAssembly и ресурсы Blazor. Статический хостинг отдаёт их браузеру. Расчёты и состояние остаются в браузере; хостинг не выполняет `SchemeRunner`. Пользователю опубликованного сайта нужен только браузер.

В прямоугольных блоках присваивание отображается через `=`, как в C#. Описание объясняет: сначала вычислить правую часть, затем заменить значение переменной. Поле начального x и поле ответа y имеют разные подписи и пояснения.
