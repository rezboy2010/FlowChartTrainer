# Размещение на GitHub Pages

Репозиторий: https://github.com/rezboy2010/FlowChartTrainer

Ожидаемый адрес после успешной публикации: https://rezboy2010.github.io/FlowChartTrainer/

## Настройка владельцем

1. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
2. Загрузить содержимое проекта в `main`, сохранив папки `src`, `tests`, `docs` и `.github`. При загрузке браузером перетаскивать папки целиком из Проводника.
3. Дождаться зелёной галочки процесса **Deploy Blazor to GitHub Pages** во вкладке **Actions**.
4. Открыть адрес из **Settings → Pages** и проверить приложение без входа в аккаунт.

Процесс можно запустить вручную через **Actions → Deploy Blazor to GitHub Pages → Run workflow**. Точная инструкция: [PUBLISH_INSTRUCTIONS.txt](../PUBLISH_INSTRUCTIONS.txt).

## Как проходит сборка

Конфигурация находится в `.github/workflows/pages.yml`. При изменении `main` GitHub Actions устанавливает SDK .NET 10, запускает консольные проверки из `tests/FlowchartTrainer.Tests`, затем выполняет `dotnet publish` веб-проекта. Ошибка проверки или сборки останавливает публикацию.

Результат — `published/wwwroot`: HTML, CSS, SVG и `_framework` со средой .NET и программой WebAssembly. В собранном `index.html` процесс устанавливает `base href` из `configure-pages.outputs.base_path`. Для данного репозитория это `/FlowChartTrainer/`. Исходный HTML сохраняет `/`, поэтому локальный запуск работает как прежде. Относительные ссылки перезагрузки также работают в подпапке.

`upload-pages-artifact` сохраняет собранные файлы, `deploy-pages` размещает их на GitHub Pages. Включены `.nojekyll` и передача скрытых файлов. Разделы переключаются внутри одной страницы; отдельных маршрутов нет, поэтому перенаправление через `404.html` не требуется.

GitHub Pages отдаёт статические файлы по HTTPS. Учебные расчёты, проверка ответов и состояние выполняются на C# в браузере посетителя. Серверной прикладной логики, регистрации и базы данных нет. При перезагрузке состояние сбрасывается.

## Локальная сборка

```powershell
dotnet publish src/FlowchartTrainer.Web/FlowchartTrainer.Web.csproj -c Release -o published
```

Или запустить `publish.bat`. На другом хостинге размещать содержимое `published/wwwroot` целиком. При размещении в подпапке нужен соответствующий `base href` и MIME `application/wasm` для `.wasm`.

## Проверка публикации

Автоматические проверки и сборка проверены в рабочей среде. Процесс GitHub Actions и публичный адрес нельзя считать проверенными до реального запуска в репозитории. После первой успешной публикации необходимо проверить ссылку в приватном окне, в другом браузере или на другом устройстве, затем дать другому ученику пройти приложение. Фактические результаты заполняются в `CLASSMATE_TEST.md`.

На защите нужно объяснить, как действие пользователя меняет состояние и экран, и показать соответствующий C#-код. Сборка Actions относится к размещению, а не к учебным расчётам.
